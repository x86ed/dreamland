## MODIFIED Requirements

### Requirement: Claude Code binds identity, telemetry, and patch-version commands to the sub-agent handoff lifecycle

In addition to the existing `SessionStart`/`Stop` bindings, the scaffold installer SHALL register `dreamland coauthor` under Claude Code's `PreToolUse` event (matcher: `Task|Agent` — the subagent-dispatch tool was renamed from `Task` to `Agent` in Claude Code v2.1.63; matching both keeps the binding correct across the VS Code extension's bundled CLI version and the standalone CLI regardless of which has updated) and `dreamland telemetry write --tool claude-code` and `dreamland version-bump --patch` under Claude Code's `SubagentStop` event, so that git identity is refreshed before every hand-off to a sub-agent, and telemetry/patch-version are refreshed on every hand-off — every agent turn — not only once per session.

The workspace-level `SubagentStop` binding SHALL NOT also register `dreamland coauthor` or `dreamland commit --reason handoff`: those two commands are agent-identity-specific, and every dreamland agent's own `.claude/agents/*.md` frontmatter already registers a `hooks.Stop` block (converted to `SubagentStop` by Claude Code's subagent-hooks mechanism, scoped to run only while that specific agent is active) carrying `coauthor --agent-name <self>` and `commit --reason handoff --agent-name <self>`. Because Claude Code runs every matching hook for an event in parallel with no ordering guarantee, registering the same two commands at both the workspace level and the per-agent level caused them to race on `git config user.name` and the handoff commit subject — the payload-resolved workspace copy could lose that race and fall through to the `janus` default even when a specific agent was correctly dispatched. Removing the workspace-level duplicate leaves exactly one writer of agent-specific git identity per hand-off.

#### Scenario: PreToolUse identity refresh before dispatch, unchanged

- **WHEN** Claude Code's `PreToolUse` hook fires for a `Task`/`Agent` tool call dispatching to `phobetor`
- **THEN** `dreamland coauthor` runs via the `PreToolUse` hook before the sub-agent's turn begins, updating `git config user.name`/`user.email` to `phobetor`

#### Scenario: SubagentStop no longer duplicates per-agent identity and handoff-commit commands

- **WHEN** `.claude/settings.json` is generated by the scaffold installer for Claude Code
- **THEN** its `SubagentStop` entry runs `dreamland telemetry write --tool claude-code` and `dreamland version-bump --patch` only
- **AND** it does not run `dreamland coauthor` or `dreamland commit --reason handoff`

#### Scenario: Per-agent frontmatter hooks remain the sole source of handoff identity and commit

- **WHEN** `morpheus`'s turn ends and its `SubagentStop`-converted `hooks.Stop` block runs
- **THEN** `dreamland coauthor --agent-name morpheus` and `dreamland commit --reason handoff --agent-name morpheus` run exactly once, from `morpheus.md`'s own frontmatter, with no workspace-level duplicate racing against them

### Requirement: dreamland commit auto-commits at end-of-turn and hand-off

`dreamland commit --reason <turn-complete|handoff>` SHALL stage all pending changes and create a commit whose subject names the reason and the resolved agent identity, when the working tree is dirty. `--reason turn-complete` SHALL first check the last recorded test result (per the `pre-merge-gate` capability's test-command gating) and refuse to commit (blocking, exit 2) if tests are known-failing at the current `HEAD`. `--reason handoff` SHALL NOT gate on test results.

For `--reason handoff` specifically, a failure in the underlying git mechanics (`git add -A`, `git commit`) SHALL be reported to the user but SHALL NOT block the sub-agent's `SubagentStop` event from completing — the command SHALL return a non-blocking error (exit 1) rather than wrapping the failure in `Blocking(...)` (exit 2), so a transient git failure during hand-off cannot trap the fixed pipeline (`nyx`→`morpheus`→`phobetor`→`baku`) mid-transition. This is unchanged for `--reason turn-complete`'s test-failure gate, which remains blocking (exit 2) by design.

#### Scenario: Handoff commit succeeds normally

- **WHEN** a sub-agent's turn ends via `SubagentStop` and `git status --porcelain` shows pending changes
- **THEN** `dreamland commit --reason handoff` stages and commits those changes with subject `chore: handoff checkpoint (<outgoing-agent-name>)` before Janus regains control

#### Scenario: Transient git failure during handoff does not block the sub-agent from stopping

- **WHEN** `dreamland commit --reason handoff` is invoked and the underlying `git commit` call fails for a reason other than "nothing to commit" (e.g. a transient lock or index error)
- **THEN** the command exits with a non-blocking status (exit code 1, not 2)
- **AND** the sub-agent's `SubagentStop` event is allowed to complete, handing off to the next agent in the pipeline, with the failure surfaced to the user

#### Scenario: Turn-complete test-failure gate remains blocking

- **WHEN** `dreamland commit --reason turn-complete` is invoked and the last recorded test result shows failure at the current `HEAD`
- **THEN** the command returns a blocking error (exit code 2), unchanged from prior behavior

### Requirement: Claude Code sub-agent identity resolution reads the SubagentStop payload's agent_type field

`dreamland coauthor` and `dreamland commit`, when invoked without an explicit `--agent-name` flag, SHALL attempt to resolve the acting agent's identity from the hook payload's top-level `agent_type` field on Claude Code's `SubagentStop` event, in addition to `tool_input.subagent_type` on `PreToolUse`/`PostToolUse` payloads for the `Task`/`Agent` tool call. Claude Code's `SubagentStop` hook input documents `agent_type` as a standard field (alongside `agent_id`, `agent_transcript_path`, and `last_assistant_message`) — an earlier assumption in this codebase that `SubagentStop` carries no sub-agent identifier at all was incorrect and is corrected by this requirement, and by `agentidentity.FromPayload`'s existing implementation.

#### Scenario: SubagentStop payload's agent_type resolves identity without --agent-name

- **WHEN** `dreamland coauthor` runs without `--agent-name` and receives a `SubagentStop` payload of `{"agent_type": "nyx", ...}` on stdin (via `--hook`)
- **THEN** `git config user.name` is set to `"nyx"`, resolved from the payload's `agent_type` field, not the `janus` fallback
