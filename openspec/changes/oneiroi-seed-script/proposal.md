## Why

Today, when `hypnos` authors a new oneiroi (per the `agent-lifecycle-management` capability's "Hypnos authors new agent definitions across every platform template" requirement), the new agent's name is picked ad hoc — by whoever writes the `phantasos`-authored change that triggers it — and `hypnos` then hand-authors all six platform template files, the routing-table edges, and the slash command from scratch for that name. There is no standard, repeatable "spin-up" scaffold, no deterministic naming convention, and no automated wiring of the boilerplate every existing oneiroi already carries identically (its own `--agent-name` hook block for `coauthor`/`telemetry write`/`commit`, per `dev-workflow-hooks`).

Separately, `agentidentity.Registered` (`internal/agentidentity/agentidentity.go`) is a hardcoded, closed set of exactly ten names. Any name `hypnos` invents for a new oneiroi cannot pass `isRegisteredAgent`/`IsRegistered` today, so a newly authored agent's git identity, telemetry, and commit trailers would silently fall back to `janus` — the exact "mystery identity" failure mode `claude-code-self-hosting` and `harden-commit-hook-enforcement` fixed for the original ten. New oneiroi are currently locked out of the identity/telemetry enforcement the rest of this system relies on.

This change gives new oneiroi a standard, scriptable naming and scaffolding path: a NICKA-style (DoD two-word code name) generator so names come from a real, repeatable word source instead of being invented, a small versioning scheme (2-word family name, a 3rd word added only on model revision or fork — the same idea as semver's major.minor.patch), and a CLI-driven scaffold step that wires the identical hook/identity boilerplate every other oneiroi already has, across every supported platform, before handing the persona-prose part back to `hypnos`.

## What Changes

- Add a checked-in seed word list (`internal/oneiroi/seedwords/words.json`) built once from the DoD/partner code-name table at https://en.wikipedia.org/wiki/List_of_U.S._Department_of_Defense_and_partner_code_names, plus a one-off, not-run-at-runtime tool that produced it, so name generation never depends on a live network fetch.
- Add `internal/agentidentity`'s open registry: a new `.dreamland/oneiroi/registry.json` file records every dynamically-seeded oneiroi (family name, up to 3 words, role, tool tier, parent-if-forked, creation/revision history). `agentidentity.IsRegistered`/`Registered` become the union of the existing closed ten plus every entry in this registry, so a seeded oneiroi's identity, telemetry, and commit trailers work exactly like the original ten's from the moment it's created.
- Add a new `dreamland oneiroi` CLI command group (Go, `cmd/oneiroi.go` + `internal/oneiroi`):
  - `dreamland oneiroi seed --role "<one-line role>"` — draws a new, collision-free 2-word family name, registers it, and scaffolds the identical hook/identity boilerplate block (per the `dev-workflow-hooks` capability) into stub template files for all six platforms, plus a routing-table stub edge and a per-agent slash command — everything `hypnos` currently hand-authors for that part of its job — leaving only the persona-prose body for `hypnos` to fill in.
  - `dreamland oneiroi revise --agent <name> --reason "<reason>"` — draws a fresh 3rd word for an existing family when its underlying model changes, updates the registry and every scaffolded file's identity references.
  - `dreamland oneiroi fork --agent <parent> --role "<one-line role>"` — creates a new family sharing the parent's 2-word major/minor pair plus a fresh, collision-free 3rd word, scaffolding a fully separate agent identity that is neither the parent's revision nor a competitor for the same 2-word family.
- Every `dreamland oneiroi *` invocation that produces or modifies files stages exactly those files and creates its own commit, authored as the script itself (`git commit --author "dreamland-oneiroi-seed <oneiroi-seed@github.com>"`), with a commit message that states `Tokens: input=0 output=0 cached=0 total=0` up front and a new `Generated-By: dreamland-oneiroi-seed` trailer — no `Co-authored-by:` trailer is added. `dreamland coauthor --trailer` (the `prepare-commit-msg` hook's Go-side handler) is extended to recognize the `Generated-By:` trailer already present on a commit message and skip both the `Co-authored-by:` append and the `Tokens:` append it would otherwise perform, so the hook still runs (nothing is skipped with `--no-verify`) but treats the message as already, deliberately, fully authored.
- Update `hypnos`'s instructions (all six platforms) so step 1 of authoring a new agent is calling `dreamland oneiroi seed --role "<description>"` for the name and boilerplate scaffold, rather than inventing a name and hand-authoring the hook block; `hypnos` then edits the persona-prose body of the stub files it produced (its existing steps 2-3 for tool tier and routing-table placement are otherwise unchanged) and calls `dreamland oneiroi revise`/`fork` when a `zhougong`-recommended or user-requested change is a revision or fork of an existing oneiroi rather than a brand-new one.
- Generalize `internal/scaffold`'s per-platform agent/hook/command installers so they can target an arbitrary agent name and tool tier supplied at call time, not only the fixed ten baked into today's template set — this is the mechanism `dreamland oneiroi seed` calls into for the boilerplate-scaffold part of its job.
- Add MCP exposure as a thin, optional wrapper: `dreamland mcp-serve` (stdio MCP server) exposes `oneiroi_seed`, `oneiroi_revise`, and `oneiroi_fork` as MCP tools that call the exact same Go functions the CLI subcommands call — no separate logic path, so behavior (including the git-commit provenance rule above) is identical whether invoked via CLI or MCP.

## Capabilities

### New Capabilities
- `oneiroi-seed-naming`: NICKA-style name generation, the up-to-3-word versioning scheme, the seed/revise/fork CLI commands, the open agent registry, and the self-authored commit provenance rule.

### Modified Capabilities
- `dev-workflow-hooks`: `dreamland coauthor --trailer` gains the `Generated-By:` trailer recognition that suppresses the `Co-authored-by:`/`Tokens:` auto-append for script-authored commits.
- `agent-scaffolding`: the per-platform agent/hook/command installers are generalized to accept an externally supplied agent name and tool tier (used by `dreamland oneiroi seed`), in addition to their existing fixed-ten-agent install path, which is unchanged.
- `agent-lifecycle-management`: `hypnos`'s "authors new agent definitions" requirement changes to start from `dreamland oneiroi seed`'s generated name and stub scaffold instead of an ad hoc invented name; adds `dreamland oneiroi revise`/`fork` as the mechanism for model-revision and fork requests.
- `router-slash-commands`: the "each non-router agent has an explicit, named direct-invoke slash command" requirement extends to cover dynamically seeded oneiroi names, not only the fixed nine.

## Impact

- Code: new `cmd/oneiroi.go`, `cmd/mcpserve.go`; new `internal/oneiroi/` package (`seed.go`, `registry.go`, `words.go`, `commit.go`); `internal/agentidentity/agentidentity.go` (open registry union); `internal/scaffold/scaffold.go` (generalized installer entry points); `cmd/coauthor.go` (`Generated-By:` trailer recognition).
- Data: new `internal/oneiroi/seedwords/words.json` (checked-in, generated once from the Wikipedia DoD/partner code-name list — see design.md for the generation mechanism); new `.dreamland/oneiroi/registry.json` (created per-repo on first `dreamland oneiroi seed`).
- Templates: `internal/scaffold/templates/agents/*/hypnos.*` (all six platforms) updated to call `dreamland oneiroi seed`/`revise`/`fork` as step 1 of authoring/revising/forking an agent.
- Specs: `openspec/specs/oneiroi-seed-naming/spec.md` is new; `dev-workflow-hooks`, `agent-scaffolding`, `agent-lifecycle-management`, and `router-slash-commands` get delta updates.
- No breaking change to the `dreamland` CLI's existing command surface — `oneiroi` and `mcp-serve` are new, additive subcommands; existing `coauthor`/`commit`/`version-bump` flags are unchanged.
