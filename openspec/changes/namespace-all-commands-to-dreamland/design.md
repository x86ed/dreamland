## Context

`platformCommandSpec` in [scaffold.go](internal/scaffold/scaffold.go:49-65) documents that a real, file-based, project-scoped slash-command mechanism only exists for **Cursor** (`.cursor/commands/*.md`, installed by `installCommands`/`installFlatAgents` from `internal/scaffold/templates/commands/cursor/`). For every other platform, there is no repo-installable command target (per the same comment block).

**Claude Code**: `dreamland init` installs *agents* (`.claude/agents/*.md`) but never installs commands — the `.claude/commands/*.md` and `.claude/commands/opsx/*.md` files that exist in *this* repo are hand-authored dogfood artifacts, disconnected from the template/scaffold system (confirmed by `scaffold_test.go`, which only asserts command installation for Cursor, not Claude Code).

Scope for this change is deliberately narrow: only dreamland's own agent-routing commands — `/route` and the nine per-agent commands (`/phantasos`, `/nyx`, `/morpheus`, `/phobetor`, `/baku`, `/iktomi`, `/zhougong`, `/hypnos`, `/mengpo`) — get the `drmlnd:` prefix. `/opsx:*` commands are OpenSpec-workflow commands, not dreamland-specific, and keep their current names. VSCode-level settings (e.g. `chat.useCustomAgentHooks`) aren't slash commands dreamland owns and aren't touched.

## Goals / Non-Goals

**Goals:**
- `/route` and the nine per-agent commands carry a `drmlnd:` prefix everywhere they're actually installed today: this repo's hand-authored Claude Code files, and Cursor's templated+installed files.
- Janus's routing table and README.md are updated to match the new names.
- Re-running `dreamland init` on a repo with old unprefixed `route`/per-agent Cursor command files removes them rather than leaving both versions installed.
- Newly exported Go identifiers get godoc; changed packages reach ≥95% line coverage.

**Non-Goals:**
- Renaming or touching `/opsx:propose`, `/opsx:explore`, `/opsx:apply`, `/opsx:archive` in any way — they are explicitly out of scope.
- Adding a real slash-command mechanism to platforms that don't have one today (Codex, GitHub Copilot, Kiro, Antigravity). Their agent instruction templates don't mention `/route` or per-agent command names as invocation strings today (they route via the `agents:` frontmatter / prose delegation, not a slash-command string), so there's nothing to rename there.
- Touching VSCode settings/commands (`chat.useCustomAgentHooks`, hook bindings) — not a slash command dreamland owns.
- Automatically migrating command files inside *other users'* repos that already ran an older `dreamland init`. The cleanup requirement only covers what `dreamland init` does the next time it runs there.
- Changing agent behavior, routing logic, or hand-off machinery — this is a naming/path change only.

## Decisions

**Directory-based namespacing for Claude Code.** Claude Code resolves a colon-namespaced command (e.g. `/drmlnd:phantasos`) from a nested directory under `commands/` (the same convention this environment already uses for names like `caveman:cavecrew-builder`). So this repo's hand-authored files move:
- `.claude/commands/route.md`, `.claude/commands/phantasos.md`, etc. → `.claude/commands/drmlnd/route.md`, `.claude/commands/drmlnd/phantasos.md`, etc.
- `.claude/commands/opsx/**` is untouched — it stays exactly where it is.

No scaffold Go code is involved in this half — these files aren't generated by `scaffold.go` at all, so it's a plain file move plus in-place text updates to self-references and to `README.md`.

**Cursor: rename the templated/installed files and update `installCommands`.** `internal/scaffold/templates/commands/cursor/{route,phantasos,nyx,morpheus,phobetor,baku,iktomi,zhougong,hypnos,mengpo}.md` are renamed/updated so the installed filenames produce `drmlnd:`-prefixed command names once copied to `.cursor/commands/`. *Open question below*: Cursor's exact namespacing convention (nested folder vs. a literal prefix character in the filename) needs verification against Cursor's own docs before implementation picks a file layout — `installFlatAgents` copies `templateDir`'s tree as-is, so whatever directory shape we put under `commands/cursor/` is what lands under `.cursor/commands/`.

**Stale-file cleanup lives in `installCommands`, not a separate command.** Rather than a new `dreamland cleanup` subcommand, `installCommands` (Cursor's path) gains a small step that removes the ten previously-known unprefixed command filenames (`route.md` + the nine agent names) from `.cursor/commands/` before/while installing the prefixed replacements, so a plain re-run of `dreamland init` self-heals. This repo's own hand-authored Claude Code files are cleaned up once, by hand, as part of this change's tasks — there's no runtime code path for it since those files were never scaffold-installed.

## Risks / Trade-offs

- **[Risk]** Cursor's actual namespace-resolution behavior for nested command directories or colon-containing names is unverified from inside this session → **[Mitigation]** tasks.md includes an explicit verification step (check Cursor's docs / experiment with a real Cursor install) before finalizing the file layout under `commands/cursor/`; fall back to a literal-prefix filename (e.g. `drmlnd.phantasos.md`) if nested namespacing isn't supported.
- **[Risk]** This is a **BREAKING** rename — any user muscle memory or external docs referencing `/route`, `/phantasos`, etc. stops working → **[Mitigation]** proposal.md already flags this as BREAKING; README is updated in the same change so the shipped docs never describe the old names. `/opsx:*` is deliberately left alone to minimize the blast radius.
- **[Risk]** Because Claude Code commands were never actually scaffold-installed, there's no automatic way to fix already-cloned user repos that hand-copied the old unprefixed files → **[Mitigation]** none needed beyond documentation, since those files were never a supported install target in the first place (only this repo's own dogfood copy).

## Migration Plan

1. Rename this repo's own `.claude/commands/{route,phantasos,nyx,morpheus,phobetor,baku,iktomi,zhougong,hypnos,mengpo}.md` into `.claude/commands/drmlnd/**`, updating internal cross-references and README. Leave `.claude/commands/opsx/**` untouched.
2. Rename/update the corresponding `internal/scaffold/templates/commands/cursor/*.md` files (per the namespacing decision above) and adjust `installCommands`/`installFlatAgents` if the new layout needs directory-walking instead of a flat copy.
3. Add the stale-file cleanup step to Cursor's install path, scoped to only the ten known route/per-agent filenames.
4. Update Janus's own routing-table instructions to reference the new prefixed names.
5. Update `router-slash-commands` capability spec (already drafted in this change) and `README.md`.
6. Add/extend Go tests for the renamed install paths and cleanup behavior; confirm coverage.

No runtime rollback concerns — this ships as a normal code change; reverting the commit reverts the naming.

## Open Questions

- Does Cursor support colon-style command namespacing from a nested directory (matching Claude Code's convention), or does it only support flat filenames? Determines the exact file layout under `internal/scaffold/templates/commands/cursor/`.
- Should `dreamland init`'s stale-file cleanup for Cursor be unconditional, or gated behind `--force` like other overwrite behavior in `installFlatAgents`? Leaning toward unconditional (removing a renamed file isn't the same risk class as overwriting user edits), but worth confirming during implementation.
