## Why

`claude-code-self-hosting` made dreamland's agent-identity resolution *correct* for Claude Code's real hook payload shape. A subsequent hooks audit found that correctness alone doesn't matter, because enforcement of that identity — and of the other invariants the Stop/SubagentStop hook chain is supposed to guarantee (a real commit every turn, no commit over failing tests, the right agent's name on both the git author and the commit subject) — is entirely advisory. Every one of the six failure modes below degrades silently instead of blocking:

1. `agentNameFromHookPayload()` (`cmd/coauthor.go:121`, and the identical pattern in `cmd/version_bump.go`'s `--if-agent` path) waits a fixed 200ms for the hook payload on stdin, then silently returns `""` — indistinguishable from "no payload was ever going to arrive." A payload that legitimately arrives in 250ms produces the exact same generic fallback as no sub-agent dispatch happening at all.
2. `Execute()` (`cmd/root.go`) always calls `os.Exit(1)` on any error. Claude Code only treats exit code 2 as blocking; every other nonzero code is advisory and the lifecycle event proceeds regardless. So today, no dreamland hook failure — not a git-config write failure, not a real test failure — ever actually blocks anything.
3. Directly downstream of (2): the Stop hook chain runs `test` then unconditionally runs `commit --reason turn-complete` next, with nothing gating the latter on the former's outcome. `dreamland test` does propagate the real nonzero exit code when the configured test command fails, but nothing stops `dreamland commit` from checkpointing a commit over that failure anyway.
4. `SubagentStop` payloads on Claude Code carry no `subagent_type` field at all (only `PreToolUse`/`PostToolUse` for the `Task` call do), so `dreamland coauthor` running on `SubagentStop` always resets identity to the Claude-Code fallback (`janus`) by design. This is exactly the end-to-end behavior `claude-code-self-hosting` tasks 6.4 and 7.3 were meant to verify live, and per that change's own record they're still unchecked — blocked because the environment that authored them had no `Task` tool available to trigger a real sub-agent dispatch.
5. `cmd/commit.go:55`'s `runCommit` resolves the checkpoint commit's *subject line* via a bare `resolveAgentName(cfg.CodingTool)` call — no registered-agent check, no Claude-Code-to-`janus` correction. The git author (set by `coauthor`) can correctly read `janus`/`nyx`/etc. while the commit subject still says `(Claude Code)`.
6. The two installed git hooks disagree on fail-open vs fail-closed for the exact same condition ("`dreamland` isn't resolvable on `PATH`"): `.git/hooks/commit-msg` (installed by `dreamland telemetry install` / `internal/scaffold/hook.go`) guards with `command -v dreamland` and silently no-ops, always exiting 0; `.git/hooks/prepare-commit-msg` (installed by `installPrepareCommitMsgHook` in `cmd/coauthor.go`) has no such guard and hard-aborts the commit if `dreamland` can't be resolved. No documented reason for the asymmetry — and per the spec (`openspec/specs/otel-commit-hook/spec.md`, "Hook appends AI telemetry as git trailers"), the commit-msg hook's silent-no-op behavior is explicitly the *specified*, intentional design today.

Separately, and structurally underneath all six: nothing in this repo rebuilds or reinstalls the `dreamland` binary when its source changes. This is literally what caused the bug `claude-code-self-hosting` fixed in the first place — the installed binary (`~/.local/bin/dreamland`, which wins on `PATH`, and the repo-root `./dreamland`) silently drifted out of sync with source and ran stale identity-resolution logic for an extended period with no signal that it had happened. Without a freshness check, every fix in this change can silently regress the next time someone touches `agentidentity`/`coauthor`/`commit`/`test` and forgets to rebuild and reinstall.

**Governing principle for this whole change**: the user wants these agent-identity and commit transitions *enforced* by the hooks, not best-effort — "not something that can fail" silently. Every decision below favors fail-loud/fail-closed over fail-open wherever the current code is ambiguous about intent, and favors proving a fix through the real, automated hook flow over a synthetic or manual one-off verification — this repo already rejected the latter approach once, in `claude-code-self-hosting` tasks 6.4/7.3.

## What Changes

- Raise `agentNameFromHookPayload`'s stdin-read timeout (200ms → 500ms) and make a timed-out read observably different from a payload that legitimately carried no agent identifier, instead of collapsing both to the same silent `""`.
- Give `dreamland` a real blocking exit code: introduce a `BlockingError` marker (`cmd/hookexit.go`) that `Execute()` (`cmd/root.go`) maps to exit code 2 (Claude Code's actual "block this lifecycle event" signal), while genuine skip conditions (no git repository, clean tree, nothing configured) keep exiting 0 exactly as they do today. `coauthor`, `commit`, and `test` are updated to use this distinction instead of collapsing every non-skip outcome into the same advisory `os.Exit(1)`.
- Gate `dreamland commit --reason turn-complete` on the immediately preceding `dreamland test` run's outcome via an explicit state file (`.dreamland/last-test-result.json`), rather than relying on undocumented Claude Code behavior about whether an exit-2 hook halts its sibling commands in the same hooks array.
- Fix `dreamland commit`'s checkpoint-commit subject line to read the same persisted identity `coauthor` already set (`git config --local user.name`) instead of independently re-resolving it — the two can never diverge again, including across hook events (`Stop` vs `SubagentStop`) where independent re-resolution would see different payload shapes.
- Make `.git/hooks/commit-msg`'s "`dreamland` not on PATH" case fail loud (block the commit) instead of silently no-opping, matching `.git/hooks/prepare-commit-msg`'s existing (previously undocumented) fail-closed behavior for the same condition. "No telemetry data available" remains a non-blocking, silent no-op — that's a different, legitimate condition.
- Close out `claude-code-self-hosting` tasks 6.4 and 7.3 as a byproduct of this change's own implementation: the real `Task`/`Agent`-tool sub-agent delegations Janus performs to dispatch this change's own tasks are the live verification those tasks were blocked on, not a synthetic one-off.
- Add a build-freshness signal: embed the source-tree git SHA into the `dreamland` binary at build time (`-ldflags`), expose it via a new `dreamland version` command, and warn loudly on stderr (non-blocking) whenever `dreamland` is invoked from inside its own source repository and the embedded SHA doesn't match that repository's current `HEAD`.

## Capabilities

### Modified Capabilities
- `dev-workflow-hooks`: `coauthor`'s hook-payload timeout and observability, a new cross-cutting exit-code contract (blocking vs advisory) for `coauthor`/`commit`/`test`, `test`'s new failure-result state file, `commit`'s test-gating and shared-identity subject line, and a new binary-freshness-warning requirement.
- `otel-commit-hook`: the `commit-msg` hook's "`dreamland` not found" case becomes blocking instead of a silent no-op; the "no telemetry data" case is unchanged.

## Impact

- Code: `cmd/coauthor.go` (`agentNameFromHookPayload`, `hookPayloadReadTimeout`, new `resolveEnforcedAgentName`/`currentGitIdentityName` helpers), `cmd/commit.go` (`runCommit`), `cmd/test.go` (`runTest`, new `.dreamland/last-test-result.json` writer), new `cmd/hookexit.go` (`BlockingError`), new `cmd/testresult.go` (shared read/write for the test-result state file), new `cmd/version.go` (`dreamland version`, build-freshness warning), `cmd/root.go` (`Execute`, freshness-check wiring), `internal/config/config.go` (`ErrNoGitRepo` sentinel), `internal/scaffold/templates/hooks/commit-msg` (fail-closed on missing binary), `cmd/version_bump.go` (`--if-agent` path shares the raised timeout).
- Specs: `openspec/specs/dev-workflow-hooks/spec.md` and `openspec/specs/otel-commit-hook/spec.md` get delta updates.
- Docs: `README.md`'s build instructions gain the `-ldflags` build-SHA invocation.
- This repository: `~/.local/bin/dreamland` and the repo-root `./dreamland` get rebuilt with the new ldflags-aware build command as part of implementation, so this repo's own dogfood installation isn't immediately stale the moment this change lands.
- No breaking change to the `dreamland` CLI's public command surface for existing users — `coauthor`, `commit`, `test`, `version-bump` keep their existing flags; `version` is a new, additive subcommand.
