## Context

`claude-code-parity` gave every dreamland agent a scoped `hooks.Stop` block in its `.claude/agents/*.md` frontmatter (`coauthor --agent-name <self>`, `telemetry write`, `version-bump` ×2, `commit --reason handoff --agent-name <self>`), mirroring the workspace-level `.claude/settings.json` `SubagentStop` array that predates it. That change's own live-verification tasks (10.x in its `tasks.md`) were never run against a real Claude Code session — confirmed by reading that file's checkboxes directly. Live use now surfaces what verification would have caught: Claude Code's hooks reference states plainly that "all matching hooks run in parallel" and that subagent-frontmatter hooks are additive, not a replacement for workspace-level ones — so both the per-agent `hooks.Stop`→`SubagentStop` conversion and the workspace `SubagentStop` array fire for the same event, racing on `git config user.name` and the handoff commit subject. The workspace array's copy resolves identity from the hook payload (`agentNameFromHookPayloadFrom`), so an ordering loss there can fall through to the `janus` default specified by `session-agent-identity` — which is meant to be a rare, no-agent-dispatched-yet default, not something a live handoff regresses into.

Separately, `guard-artifact` (from the same change) enforces `tasks.md` as `phantasos`-exclusive, which conflicts with `morpheus.md`'s own documented instruction ("Mark each task complete... immediately after finishing it") — the guard was scoped to the whole file when it should only have protected the file's prose content.

Third, `cmd/commit.go`'s `--reason handoff` path wraps every git failure (including transient ones) in `Blocking(...)`, which maps to exit 2. Per Claude Code's hooks reference, exit 2 on `SubagentStop` "prevents the subagent from stopping" — so a flaky `git commit` doesn't just fail visibly, it traps the subagent, breaking the fixed hand-off chain (`nyx`→`morpheus`→`phobetor`→`baku`) the `janus-router-agent` capability depends on.

## Goals / Non-Goals

**Goals:**
- Make agent git identity during a handoff deterministic: exactly one hook path sets it, matching the dispatched agent, every time.
- Let the agent responsible for a task's implementation check it off in `tasks.md` without guard interference, while keeping `phantasos` as the sole owner of the file's prose.
- Ensure a transient git failure during handoff surfaces to the user instead of blocking the subagent from stopping.
- Correct the stale spec claim about Claude Code's `SubagentStop` payload shape.

**Non-Goals:**
- Not revisiting the `janus` fallback default itself (`session-agent-identity` already specifies it for the no-agent-dispatched-yet case) — only removing the race that causes it to fire when an agent *has* been dispatched.
- Not changing GitHub Copilot's hook wiring — its `SubagentStart`/`SubagentStop` are Copilot-native events with no workspace-level duplicate of this shape; this bug is Claude Code-specific.
- Not relaxing `guard-artifact` for any file/agent pairing other than the documented `tasks.md` checkbox case.
- Not making the `--reason turn-complete` test-failure gate non-blocking — that gate is intentional and unrelated to this bug.

## Decisions

**Remove the workspace-level `SubagentStop` identity/handoff duplicate rather than removing the per-agent frontmatter hooks.** The per-agent hooks are the ones Claude Code's own subagent-hooks mechanism scopes precisely to "while that subagent is running," and they already carry the exact agent name as a static `--agent-name` flag — no runtime payload parsing, no ambiguity. The workspace-level copy exists only because it predates per-agent hooks; keeping the workspace-level `PreToolUse(Task|Agent)` `coauthor --hook` entry (which runs in the *parent's* turn, before dispatch, not a duplicate of anything) means identity is still refreshed the instant a sub-agent is chosen, and the (now sole) `SubagentStop`-scoped identity/telemetry/commit commands come from the dispatched agent's own file.

**Scope the `tasks.md` guard exception to checkbox-only edits, not the whole file.** Rather than removing `tasks.md` from the ownership table entirely (which would let any agent rewrite task descriptions), `guard-artifact` gains a narrow check: an `Edit` tool call against a protected `tasks.md` path is allowed regardless of `agent_type` when its `old_string`/`new_string` diff is a checkbox-state flip only (`- [ ]` ↔ `- [x]`, same task text otherwise). A `Write` (full overwrite) or an `Edit` that changes anything beyond the checkbox marker still requires `phantasos`. This preserves the guard's actual purpose (protect authored content) without blocking the one edit every implementer is instructed to make.

- *Alternative considered*: drop `tasks.md` from the ownership table entirely. Rejected — it would let any agent rewrite task scope/descriptions mid-implementation, defeating the reason the table exists.
- *Alternative considered*: grant `morpheus`/`nyx`/`hypnos`/`mengpo` as additional owners of the whole file. Rejected — same problem, just with an explicit allowlist instead of no protection; the checkbox-diff check is more precise and doesn't need updating every time a new implementer agent is added.

**`commit --reason handoff`'s git-mechanics failures return a plain (non-`Blocking`) error.** This is exit 1 under `cmd/root.go`'s existing `Execute()` mapping, which Claude Code's hooks reference confirms is non-blocking for `SubagentStop` ("any exit code other than 2 doesn't block... execution proceeds, and the transcript shows a hook error notice"). The user still sees the failure; the subagent still hands off. The `--reason turn-complete` test-failure gate keeps using `Blocking(...)` — untouched by this decision, since blocking a stop on failing tests is the intended, previously-specified behavior for that path only.

**Fix the spec prose, not just the code.** `dev-workflow-hooks`'s existing text asserting Claude Code's `SubagentStop` payload carries no identifier is simply wrong per Claude Code's current hooks reference (`agent_type` is documented on `SubagentStop` input) — `agentidentity.go`'s own doc comment already notes this was "an earlier assumption in this codebase... corrected." The spec delta brings the written requirement in line with what the code (and the platform) actually does, so the next reader doesn't re-introduce the stale assumption.

## Risks / Trade-offs

- [Risk] Removing the workspace-level `SubagentStop` duplicate could leave built-in agents (`general-purpose`, `Explore`, `Plan`) — which have no `.claude/agents/*.md` file of their own, hence no per-agent frontmatter hooks — without any `SubagentStop` telemetry/identity coverage. → Mitigation: keep a workspace-level `SubagentStop` entry for `telemetry write --tool claude-code` and `version-bump --patch` (the two commands that don't carry agent-identity-specific flags and apply uniformly), and remove only `coauthor`/`commit --reason handoff` from the workspace level, since those two are the ones duplicated verbatim (identity + name) by every dreamland agent's own file. Built-in agents still get telemetry coverage per the existing `agent-telemetry-coverage` capability; they simply don't get a `--reason handoff` commit under their own name, which was already true before `claude-code-parity` (their identity resolution goes through the payload-based path, not a static flag, and isn't changing here).
- [Risk] The checkbox-diff heuristic in `guard-artifact` could be bypassed or produce false negatives on unusual whitespace/formatting in `tasks.md`. → Mitigation: normalize whitespace before comparing, and fail closed (still require `phantasos`) on anything the heuristic can't confidently classify as checkbox-only — the guard's existing fail-open behavior is reserved for *unknown identity*, not *ambiguous diff shape*.
- [Risk] Removing `Blocking(...)` from `commit --reason handoff` means a genuinely broken git state (e.g. detached HEAD, corrupted index) now fails silently from the subagent's perspective. → Mitigation: the failure is still surfaced via stderr/systemMessage per Claude Code's exit-1 handling, so the user sees it even though the subagent isn't trapped; this trades "subagent can't get stuck" for "user must notice a warning," which matches this change's stated goal of not blocking chaining.
