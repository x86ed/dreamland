## Why

The scaffolded agent templates give every platform an `orchestrator` agent, but it has no enforced routing contract, no restricted tool set, and no wiring to the lifecycle hooks that already exist (`dreamland coauthor`, `dreamland telemetry`). Routing decisions and identity/telemetry bookkeeping currently only fire once per session (`SessionStart`/`Stop`), not on each agent handoff, so the git author and telemetry stream don't reflect which agent/model actually did the work. Renaming and hardening this agent as a dedicated router — Janus — with explicit tool bindings, slash-command entry points, and per-handoff hook invocation closes that gap. Separately, implementation work today goes straight from spec to code with no enforced test-first discipline, and free-form requests that don't fit the OpenSpec change lifecycle at all have no clear owner. Finally, the agent roster itself has no feedback loop: nothing looks at git history, token burn, or turn duration to say which agents are earning their keep, nothing authors a new agent when a gap is found, and nothing retires one that's no longer needed — a wider agent set closes all of these gaps at once.

## What Changes

- Rename `orchestrator` to `janus` across all six platform templates (Claude Code, Codex CLI, Cursor, Kiro, Antigravity, GitHub Copilot). **BREAKING**: existing `orchestrator.*` files and references are replaced; any user content in a pre-existing `orchestrator` file is not migrated automatically. Janus (Roman two-faced god of doorways and transitions) takes over the router role.
- Rename `pr-closer` to `baku` (獏, the dream-eating spirit) across the same six platform templates, keeping its role and responsibilities unchanged. **BREAKING**: same caveats as above.
- Rename `spec-writer` to `phantasos` (Oneiroi, shaper of imagined forms), keeping its role unchanged. **BREAKING**: same caveats as above.
- Rename `implementer` to `morpheus` (Oneiroi, shaper of human-form dreams), keeping its role unchanged. **BREAKING**: same caveats as above.
- Rename `tester` to `phobetor` (Oneiroi, bringer of nightmares), keeping its validation role unchanged: run the test suite, check each task against its spec scenario, report failures. **BREAKING**: same caveats as above.
- Add a brand-new agent, `nyx` (primordial goddess of Night, mother of Hypnos): writes the acceptance test for a task, from its spec scenario, before implementation exists (TDD red phase) — but only for tasks that warrant one. No predecessor to rename from; granted file-editing tools (creates test files).
- Add a brand-new agent, `iktomi` (Lakota trickster spider spirit): a free-form, general-purpose coding agent for requests that don't fit the OpenSpec-driven flow at all. Selected by Janus only when no specialized agent matches. Also granted file-editing tools, and subject to the same `dreamland coauthor`/`telemetry write` hand-off machinery as every other agent — no special-casing.
- Add a brand-new agent, `zhougong` (周公, Duke of Zhou — dream interpretation figure in Chinese folklore): reads git history, per-agent token burn (from the `Tokens:` commit trailer), and turn duration (from `.dreamland/transition.log`) and generates reports under `.dreamland/reports/` with tuning suggestions and, when warranted, a recommendation to author a new agent. Granted `Write` (new report files) but not `Edit` — it never modifies an existing file.
- **Reuse the name `hypnos` for an entirely new role**: the router moves to `janus`, freeing `hypnos` to become the agent that **authors new agent definitions** — across all six platform templates, from a direct request or from a `zhougong` report's recommendation — and registers them with Janus's routing table and per-agent slash command set. Granted full `Edit`/`Write` (it edits Janus's routing table as part of registering a new agent).
- Add a brand-new agent, `mengpo` (孟婆, goddess of forgetting in Chinese folklore): archives (default) or, on explicit instruction, permanently deletes agent template files that are no longer needed, removing them from Janus's routing table and command set, and recording the action in `.dreamland/archived-agents.md`. Granted `Write` (archive manifest) but not `Edit`.
- The implementation workflow is **not strictly linear**: Janus chooses, per task, between two valid flows — a direct-implementation flow (spec → `morpheus` → `phobetor` → `baku`) for mechanical/internal changes, and an acceptance-test flow (spec → `nyx` → `morpheus` → `phobetor` → `baku`) for tasks that implement new, externally-observable behavior with no existing covering test. Both converge at `phobetor`/`baku`. Agent-roster-maintenance requests (analytics, authoring, archival) are routed separately, to `zhougong`/`hypnos`/`mengpo`, and never enter either implementation flow.
- Add router-only annotations to Janus's frontmatter/instructions (e.g. a `role: router` marker and explicit "you do not write code or specs yourself" framing) so it only ever delegates, never edits files directly.
- Restrict Janus's tool bindings per platform to read/dispatch tools only (e.g. `Read, Bash` for Claude Code — no `Edit`/`Write`), and add the equivalent restricted tool bindings for Codex, Cursor, Kiro, Antigravity, and Copilot templates.
- Add a routing table to Janus's instructions covering all nine other agents, including the two-flow entry decision, the `iktomi` fallback, and the `zhougong`/`hypnos`/`mengpo` agent-roster-maintenance targets. **The workflow is not a router-mediated chain end-to-end**: Janus decides the entry point and handles ambiguous/terminal cases, but deterministic mid-pipeline hand-offs (`nyx`→`morpheus`, `morpheus`→`phobetor`, `phobetor`→`baku`/`morpheus`/`phantasos`, `hypnos`→`phobetor`) go directly agent-to-agent, without reporting back to Janus first.
- Add a generic `/route` slash command that invokes Janus directly for requests not already covered by an `/opsx:*` command.
- Add one explicit, named slash command per non-router agent — `/phantasos`, `/nyx`, `/morpheus`, `/phobetor`, `/baku`, `/iktomi`, `/zhougong`, `/hypnos`, `/mengpo` — that tells Janus to route directly to that agent, overriding Janus's own judgment while still going through Janus for the identity/telemetry hand-off bookkeeping.
- Fix every scaffolded agent's hand-off language so each hop is deliberate, not accidental: today `implementer` escalates ambiguity straight to `spec-writer` and `tester` reports failures straight to `implementer` on all six platforms, and both happen to be reasonable deterministic edges under this change's model — but today they exist by accident, not by design, with no distinction anywhere between "fixed next step" and "needs judgment," and no per-hand-off identity/telemetry hook coverage (that only fired once per session). This change keeps the direct hand-offs where they're actually deterministic, adds the spec-vs-implementation distinction Phobetor's failure branch needs, and — separately — extends the coauthor/telemetry hooks to fire on every hand-off regardless of which agent initiates it (see the `dev-workflow-hooks` capability), which is what was actually missing, not the directness of the hand-off itself.
- Formalize each agent's tool bindings as an explicit, three-tier per-role matrix: full-edit (`phantasos`/`nyx`/`morpheus`/`iktomi`/`hypnos`), read-only/dispatch (`janus`/`phobetor`/`baku`), and write-only-no-edit (`zhougong`/`mengpo`).
- Give `iktomi` and the agent-roster-maintenance trio (`zhougong`, `hypnos`, `mengpo`) broad routing capability — unlike the narrow pipeline agents, each of these four may hand off directly to *any* other agent when its own work points there (the same fan-out Janus itself has), and reports to Janus only when it doesn't. This reflects that their work — free-form coding, cross-cutting analytics, agent authoring, agent retirement — routinely touches parts of the system a narrow pipeline agent never would; it also closes the Janus↔Iktomi loop both ways (Janus dispatches free-form work to Iktomi; Iktomi can dispatch onward to a specialist or back to Janus).
- On GitHub Copilot (VS Code) specifically, declare each agent's subagent-invocation graph and applicable hooks structurally in its frontmatter (`agents:`, `hooks:`) — that platform requires the hand-off graph declared upfront, not left to prose alone the way Claude Code allows. `janus.agent.md` and the four broad-routing agents (`iktomi`, `zhougong`, `hypnos`, `mengpo`) each list all nine other agents; `morpheus.agent.md` additionally lists `phobetor`; `phobetor.agent.md` additionally lists `baku`, `morpheus`, and `phantasos` (its success/spec-failure/implementation-failure branches); `phantasos`, `nyx`, and `baku` each list only `janus`.
- GitHub Copilot's VS Code agent framework has a real, workspace-scoped hooks file (`.github/hooks/*.json`, publicly documented as of February 2026), the same shape as every other platform's hook binding — no per-agent `hooks:` frontmatter field. `dreamland` binds the normalized four-command set — `coauthor`, `telemetry write`, `commit`, `version-bump` — to that file's `SessionStart`/`SubagentStart`/`SubagentStop`/`Stop` events. This guarantees, on GitHub Copilot exactly as on every other platform, that every agent's turn keeps git identity current (`coauthor`), pushes token/model usage into the commit message (`telemetry write`, via the `Tokens:` trailer), produces a checkpoint commit for every cycle and hand-off (`commit`), and bumps the semantic version (`version-bump`) — patch by default on every turn, minor once per new change/branch (`phantasos` triggers this on `openspec new change`), major when `baku` finalizes a change marked **BREAKING** — so no agent's activity goes uncaptured in git history or the version history. Every agent's frontmatter also includes `agent` in its `tools:` list whenever it has a non-empty `agents:` list, since VS Code's custom-agent framework requires the invoking agent to hold the `agent` tool before its `agents:` restriction has any effect.
- Extend hook bindings so lifecycle commands fire on every agent handoff, not just session start/stop: bind `dreamland coauthor` and `dreamland telemetry write` to fire whenever any agent dispatches to a sub-agent (Janus at an entry point, or another agent making a deterministic hand-off) and when that sub-agent's turn completes, so `git config user.name`/`user.email` and the telemetry log always reflect the currently active agent/model regardless of who initiated the hand-off. This identity/telemetry logic is identical across all ten agents — the hooks never special-case a given agent, and they fire on the underlying dispatch event (e.g. Claude Code's `PreToolUse`/`SubagentStop`), not on "Janus specifically called this."
- Extend `dreamland coauthor --trailer` (the `prepare-commit-msg` hook body) to append a token-usage report line to every commit message, alongside the existing `Co-authored-by:` trailer, sourced from the current turn's telemetry snapshot — this is also `zhougong`'s primary data source for token-burn analysis.
- Add a new `dreamland commit --reason <turn-complete|handoff>` lifecycle command that auto-commits any pending working-tree changes whenever an agent's turn completes (`Stop`) or an agent-to-agent handoff occurs (`SubagentStop`), so every state transition is captured as its own commit even if the agent never explicitly ran `git commit`.

## Capabilities

### New Capabilities
- `janus-router-agent`: The Janus agent definition installed per platform — router-only frontmatter annotations, restricted tool bindings, the two-flow (direct-implementation vs. acceptance-test) decision for implementation tasks, the `iktomi` free-form fallback, the `zhougong`/`hypnos`/`mengpo` agent-roster-maintenance routing, and the routing table used to delegate to all nine other agents.
- `router-slash-commands`: Slash command entry points across three tiers — `/opsx:*` (lifecycle-specific, either a deterministic bypass or the `/opsx:apply` two-flow decision), `/route` (generic, Janus decides), and one explicit per-agent command each for all nine non-router agents.
- `agent-lifecycle-management`: `zhougong`'s report generation (data sources, output location, tuning/new-agent recommendations), `hypnos`'s agent-authoring workflow (creating templates across all platforms, registering with Janus, adding a slash command), and `mengpo`'s archive/delete workflow (default-archive, explicit-delete, audit trail).

### Modified Capabilities
- `agent-scaffolding`: The five-agent set installed by `dreamland init` changes to a ten-agent set: `orchestrator, spec-writer, implementer, tester, pr-closer` becomes `janus, phantasos, nyx, morpheus, phobetor, baku, iktomi, zhougong, hypnos, mengpo` — with `nyx`, `iktomi`, `zhougong`, and `mengpo` wholly new agents, and `hypnos` reused for a new role (agent-authoring) distinct from its earlier router role in this same change; per-platform file names, paths, and frontmatter requirements are updated accordingly, including a third tool-binding tier (write-only, no edit) for `zhougong`/`mengpo`.
- `dev-workflow-hooks`: New hook bindings are added for the agent-handoff lifecycle (sub-agent turn start / sub-agent turn complete, e.g. Claude Code's `PreToolUse` matched on `Task|Agent` and `SubagentStop`; GitHub Copilot's own `SubagentStart`/`SubagentStop` events) so `dreamland coauthor` and `dreamland telemetry write` run on every handoff, in addition to the existing `SessionStart`/`Stop` bindings. `dreamland coauthor --trailer` gains a token-usage report line in every commit message, and a new `dreamland commit` command auto-commits pending changes on turn completion and handoff.

## Impact

- **Renamed/modified files**: `internal/scaffold/templates/agents/*/orchestrator.*` → `janus.*`, `internal/scaffold/templates/agents/*/pr-closer.*` → `baku.*`, `internal/scaffold/templates/agents/*/spec-writer.*` → `phantasos.*`, `internal/scaffold/templates/agents/*/implementer.*` → `morpheus.*`, and `internal/scaffold/templates/agents/*/tester.*` → `phobetor.*` (all six platform directories); corresponding hook binding files under `internal/scaffold/templates/hooks/bindings/*/`.
- **New files**: `internal/scaffold/templates/agents/*/{nyx,iktomi,zhougong,hypnos,mengpo}.*` (all six platform directories) — brand-new agent templates, none renamed from an existing file (`hypnos` is a new file even though the name existed earlier in this change's own history as the router — that file was renamed to `janus.*`, so `hypnos.*` starts fresh); `.claude/commands/{phantasos,nyx,morpheus,phobetor,baku,iktomi,zhougong,hypnos,mengpo}.md` (and platform equivalents) for the explicit per-agent commands; `cmd/commit.go` (the `dreamland commit` lifecycle command).
- **Modified files**: `internal/scaffold/` installer logic (file names, frontmatter content), `cmd/init.go` if agent names are enumerated there, `.claude/commands/` (new router and per-agent slash commands), `cmd/coauthor.go` (token-usage report line), `openspec/specs/agent-scaffolding/spec.md`, `openspec/specs/dev-workflow-hooks/spec.md`.
- **No new dependencies** and no new CLI commands beyond `dreamland commit` — `zhougong`, `hypnos`, and `mengpo` all operate via `git`/file operations described in their own instructions, reusing data (`Tokens:` trailers, `.dreamland/transition.log`) already produced by existing lifecycle hooks.
